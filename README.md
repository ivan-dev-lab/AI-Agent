# AI-Agent

`AI-Agent` — Telegram-бот для учебного процесса: управление учебными заведениями, классами, пользователями, заданиями и напоминаниями.

Проект построен как асинхронное Python-приложение на `aiogram`. Он использует SQLite через `aiosqlite`, планировщик `APScheduler`, роли пользователей и систему напоминаний о дедлайнах.

Несмотря на название, проект в первую очередь демонстрирует не “магического AI-агента”, а backend-логику Telegram-сервиса: маршрутизацию обработчиков, хранение состояния, роли, задания, дедлайны, расписание уведомлений и восстановление задач после перезапуска.

## Кратко

Бот позволяет:

- регистрировать пользователей;
- работать с ролями;
- создавать учебные заведения;
- назначать локальных администраторов;
- создавать классы;
- добавлять преподавателей и учеников;
- создавать задания;
- назначать задания группе или отдельным ученикам;
- отправлять уведомления о новых заданиях;
- отправлять напоминания перед дедлайном;
- хранить данные в SQLite;
- восстанавливать запланированные напоминания после перезапуска.

## Статус проекта

Статус: **рабочий прототип Telegram-бота для учебных задач**.

Реализовано:

- запуск через `src/main.py`;
- подключение Telegram-бота через `aiogram`;
- подключение нескольких router-модулей;
- инициализация базы данных;
- таблицы пользователей, классов, заданий, школ и связей;
- роли учеников, преподавателей и локальных администраторов;
- приглашения через временные токены;
- задания с дедлайнами;
- индивидуальные и групповые назначения;
- планировщик напоминаний;
- восстановление будущих jobs после перезапуска;
- работа с часовыми поясами;
- конфигурация через `.env`.

## Основная идея

Учебный процесс требует учета ролей и состояний:

- есть учебные заведения;
- есть классы;
- есть преподаватели;
- есть ученики;
- есть задания;
- у заданий есть дедлайны;
- о дедлайнах нужно напоминать;
- часть заданий может быть групповой, а часть индивидуальной.

Проект собирает это в Telegram-бота, где пользователь взаимодействует через кнопки и сообщения, а backend-часть хранит структуру учебного процесса в базе данных.

## Архитектура

Упрощенная структура:

```text
src/
  main.py                    # точка входа, запуск Bot и Dispatcher
  config.py                  # настройки и переменные окружения
  db.py                      # схема БД и функции доступа к данным
  scheduler_jobs.py          # планировщик напоминаний
  callbacks.py               # callback-идентификаторы
  keyboards.py               # клавиатуры Telegram
  utils.py                   # вспомогательные функции

  handlers/
    common.py                # общие команды
    enroll.py                # зачисление и приглашения
    tasks.py                 # задания
    students.py              # сценарии ученика
    classes.py               # классы
    teacher.py               # сценарии преподавателя
    local_admin.py           # локальный администратор
    gen.py                   # генерация/дополнительные сценарии
    text.py                  # текстовые обработчики
```

В `main.py` создается бот, инициализируется база данных, запускается планировщик и подключаются router-модули.

## Поток запуска

Упрощенно:

```text
load .env
  -> ensure_db()
  -> create Bot
  -> init_scheduler()
  -> create Dispatcher
  -> include routers
  -> start polling
```

Это стандартная архитектура асинхронного Telegram-бота: точка входа не содержит всю бизнес-логику, а подключает отдельные обработчики.

## База данных

Проект использует SQLite через `aiosqlite`.

В базе есть таблицы для:

- учебных заведений;
- классов;
- пользователей;
- связей ученик-класс;
- преподавателей;
- локальных администраторов;
- заданий;
- запланированных напоминаний;
- индивидуальных назначений;
- временных приглашений.

Примеры сущностей:

```text
schools
classes
users
enrollments
tasks
jobs
task_targets
school_local_admins
school_teachers
school_students
pending_students
pending_local_admins
```

SQLite выбран как простой локальный вариант хранения, достаточный для прототипа и учебного проекта.

## Роли пользователей

В проекте используются разные роли:

- ученик;
- преподаватель;
- локальный администратор;
- администраторские сценарии.

Роли нужны, чтобы разграничивать доступ к действиям. Например, ученик видит свои задания и дедлайны, преподаватель создает задания, а локальный администратор управляет структурой учебного заведения.

## Задания и дедлайны

Задание содержит:

- название;
- описание;
- дедлайн;
- класс;
- дату создания.

Задания могут быть:

- групповыми;
- индивидуальными для конкретных учеников.

Для этого используется таблица `task_targets`. Если у задания нет индивидуальных targets, оно считается групповым для класса. Если targets есть, задание показывается только выбранным ученикам.

## Напоминания

Для дедлайнов используется `APScheduler`.

Система умеет:

- создавать jobs для заданий;
- сохранять jobs в базе;
- отправлять напоминания ученикам;
- восстанавливать будущие jobs после перезапуска;
- учитывать часовой пояс класса;
- отправлять уведомления о новом задании;
- отправлять уведомления об обновлении задания.

Пример логики:

```text
создано задание
  -> рассчитаны даты напоминаний
  -> jobs записаны в базу
  -> APScheduler получает задачи
  -> при наступлении времени бот отправляет сообщение
```

## Установка

Требуется Python `3.11+`.

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## Конфигурация

Проект использует `.env`.

Минимально нужен токен Telegram-бота:

```text
BOT_TOKEN=...
```

Также могут использоваться настройки базы данных, часового пояса и других параметров, заданные в `config.py`.

## Запуск

```bash
python src/main.py
```

После запуска бот:

1. проверяет и создает таблицы базы данных;
2. запускает планировщик;
3. восстанавливает будущие напоминания;
4. подключает обработчики;
5. начинает polling Telegram-обновлений.
